## 0. 结论先行

1. **这件事比看上去便宜，前提是别逐候选跑 A\***。现有的替代起降点扫描之所以是全场最慢分支
   （一次实测 19~45 s），是因为它给每个候选点都做一次全程重规划。站点选址不需要——
   站点的"好坏"是**该点周围一片格点的统计性质**，一次读场 + 纯 numpy 邻域统计就能排完，
   A\* 只留给最后 Top-K 的可达性复验。**候选规划次数从 24~48 次压到 ≤8 次**，这是本方案的核心。
2. **"分段飞"几乎免费**：`_plan_seq` 本来就是按 `[start] + waypoints + [end]` 逐段搜索
   （`planner.py:851, 870-882`），前端 waypoints 的增删与地图标注也都在。所以分段飞 = 把选出来的
   中继点填进 `store.waypoints`，**寻路一行不改**。
3. **不要等 M6 的气候态产品**。M6 §8 把 P0-C 挂在"全年气候态统计"后面，但那只对"按全年可飞率
   选永久场址"必要。"给定某个时刻/某天，这条走廊上哪儿适合起降/中转"这个版本不依赖 M6，
   10-15 大赛初赛截止前能做完、能演示。气候态版留二期。
4. **一个硬阻塞，我给不了你答案**：仓库里**没有任何续航 / 最大航程 / 航时参数**
   （`config.py` 只有 A\* 展开预算 `ASTAR_EXPANSIONS_PER_KM` 与两道墙钟）。而"中途降落点/补给站"
   的全部意义就是"飞不到那么远，在哪儿歇一脚"。**没有续航口径，中继选址无从谈起**（§10 Q3）。
5. **三处数据局限决定对外话术**：气象读数全钉在 500 hPa（约 5.6 km 高空，`data_loader.py:381-388`）、
   高程数据磁盘上有但 backend 一行没读、空域/限制区零数据（B6）。所以本功能的产出只能叫
   **"高空气象口径下的候选站点"**，不能叫"可用场址"。这不是谦虚，是答辩时不被一枪打穿的唯一办法。

## 1. 需求拆解：09-24 那句话说的是三件事

对话里的"站点规划"混着三种不同产品，输入输出都不一样，必须拆开分别拍板：

| 形态 | 问的问题 | 输入 | 输出 | 本方案 |
| --- | --- | --- | --- | --- |
| **A 场址筛选** | 这条走廊/这片区域里，哪儿值得设起降场 | 区域或走廊 + 时刻/日期 | 按质量排序的 N 个点 | **一期做** |
| **B 中继选址** | 起终点已知但飞不到，中途在哪儿补给 | 起终点 + 续航上限 | 1~2 个中继点 | 二期（等 Q3 续航口径） |
| **C 分段飞** | 给出 S→R1→R2→E 的逐段计划 | B 的输出 | 多段航线 + 逐段风险 | **一期做，几乎零成本** |

"缓解无人机飞这么远有点逆天"这句是 B/C 的动机；"有些地方比较适合去做这个站点，因为总的 TKE
综合数据比较适合起飞"这句是 A。**A 是 B 的评分函数**，所以一期把 A 的机器做扎实，B 只是换个调用方式。

### 明确不做的

- 不做"站点"的实体建模（没有台站库、没有起降场工程条件：跑道、净空、电磁、通信）。
- 不做地形跟随与限制区（B6，无数据源）。
- 不做机队/任务调度（超出赛题开放式命题的范围，也超出工期）。

## 2. 与预测（M6）的关系：本方案最需要你拍板的一格

09-24 那次对话的逻辑链是：真实场景只能拿到"此刻之前"的数据 ⇒ 时间窗口该用预测 ⇒
那航线规划凭什么还用档案场？答案是"给预测找一个名正言顺的落点：站点规划"。
M6 §0.2 的范围表里没有这一格，所以两条路要选一条：

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **甲：只吃档案场**（推荐） | 选址输入 `date + start_time`，读的是已发生的分析场，与功能一同口径 | 与 M6 完全解耦，**M6 不做也能独立交付**；答辩口径统一"这是复盘/推演工具" | "预测的落点"这个叙事落空，M6 §0.2 那句"规划用档案场"仍缺一层正当性论证 |
| **乙：同时支持预测场** | 选址入参加 `mode=archive\|forecast`，forecast 分支调 M6 的预测场 | 把 09-24 的对话闭环兑现，作品方案里"预测有实际用途"讲得圆 | **绑死 M6 的排期**（M6 现在 0 行代码，估 4 天）；且给"预测的产物再喂给第三个模块"开了递归误差的口 |

我推荐**甲**，并在 `schemas` 里预留 `mode` 字段（默认 `archive`，二期填 `forecast`）。
理由不是省事，而是：M6 的预测目前只有时间窗口一个消费方，10-15 前把 M6 做完 + 做对 + 再嫁接选址，
风险全叠在一起；而选址用档案场版本自己就能演示、能填进作品方案第四章"关键环节"。

### 3.2 必须先处理的历史债（三笔，都很小）

1. **覆盖检查有三份重复实现**：`feasibility._check_coverage:328-340`、`data_loader.check_coverage:442-458`、
   `data_loader.coverage_bbox:460-482`。选址要判"候选点在不在范围内"，再加第四份就是雷。
   → 选址只调 `coverage_bbox`，并顺手把 `_check_coverage` 改成走它（一次小 PR，风险极低）。
2. **端点量化陷阱**：`_plan_seq` 把每段端点 `round(lat, 2)/round(lon, 2)`（`planner.py:874-875`）
   ≈ **1.1 km**，而替代点输出的是 `round(..., 4)`（`feasibility.py:649`）。两个相距 0.8 km 的候选
   进了 A\* 会变成同一个点，排序就会莫名其妙。
   → **候选最小间距强制 ≥ 2 km**（约 1 个格），并在输出前按 2 位小数去重。
3. **网格分辨率有两个真相**：`GRID_RESOLUTION_DEG = 0.045`（`config.py:90`）对实际数据 303×543 ≈ 0.05°。
   30°N 上一格约 **5.00 km(南北) × 4.32 km(东西)**。
   → 选址的半径参数一律以"格"为单位换算，别用 0.045 反推公里数。

### 3.3 不能碰 / 不能依赖

- `planner.py` 的代价函数、硬阈值、启发式（A4 核查的结论就靠它成立）。**选址只产出点，不产出线。**
- SRTM：`data/srtm/*.hgt` 在磁盘上但 backend 无人读（`main.py:63-82` 走的是在线 opentopodata，且只服务剖面图）。
  `README.md` 的 FastSRTM 说法与 `AGENTS.md` 相应描述均已过时。**别把海拔筛选算进一期工作量。**
- 金标 `tests/golden_plan.py` 15 例：一期不改寻路，理应逐字节不变——这本身就是验收项。

## 4. 算法设计

### 4.1 Pass 1：邻域统计选址（不跑 A\*，纯 numpy）

一次 `get_meteorology_grid(bbox)` 拿到 TKE/EDR 场，对每个格点 p 在以它半径 R 盘（R 默认 3 格 ≈ 15 km）内算四个量：

| 指标 | 定义 | 为什么是它 |
| --- | --- | --- |
| `fly_ratio` | 盘内非 NaN 格点中，TKE<8 且 EDR<对应阈值的占比 | "适合起飞"最直观的版本：周围一片都太平 |
| `worst_tke` | 盘内最大 TKE | 局部均值会掩盖一个洞，选址要按最坏值判（与 `overall_level` 取沿程最坏采样点同口径） |
| `nan_ratio` | 盘内 NaN 占比 | 数据缺失区不能当"安全"，必须显式排掉（这是现有 A\* 用 NaN 当地形障碍的镜像问题） |
| `reach_km` | 到最近已有站点（`store.bases` 4 城）的直线距离 | 让"补给网络"有空间结构，否则选出来 3 个点全挤在同一座山谷 |

排序用**字典序，不拍权重**：先过硬门槛（`nan_ratio ≤ 0.2`、`worst_tke < TKE_THRESHOLD_HIGH`），
再按 `(风险档, -fly_ratio, worst_tke, 距已有站点的可达距离)`。
理由：自造一个 `0.6·A + 0.4·B` 的加权分，答辩第一个问题就是"权重哪来的"，而字典序与
`_suggest_alt_bases` 现在的 `(RISK_ORDER, distance_km)` 排序一致（`feasibility.py:665-668`），不用另解释。

取 Pass 1 的 Top-M（M=8）进 Pass 2。M 比输出数 K=3 大一倍，是为了给 Pass 2 的可达性判据留出被刷掉的空间。

### 4.2 Pass 2：可达性复验（这里才跑 A\*）

对 M 个候选各构造一次 `PlanRequest`（起或终替为候选点），走 `plan_path_ex(req, field=注入场, deadline=共享余额)`：

- `found` 且 `path` 非空 → 用 `build_risk_profile` 出真实沿程剖面（含**按到达时刻**取数，与功能一同口径）；
- 结论 `LEVEL_UNFLYABLE` 的直接丢（与 `_suggest_alt_bases:645` 同一判据）；
- 最终排序仍是 `(RISK_ORDER, route_km)`，截断到 `SITE_MAX_RESULTS = 3`。

B/C（中继与分段）在 A 的机器上只多一步：**沿现有航线取候选锚**。先用
`build_segment_bounds` 拿到城市间隔点，再在每个间隔段内取 Pass 1 的 Top-1 作中继；
输出的中继点直接填进 `waypoints`，`_plan_seq` 自动分段。

### 4.3 输出契约

新增 `backend/sites.py`（与 `route_options.py` 平级的编排层，不放 `feasibility.py`——那文件已经 700+ 行）：

```
POST /api/site/select   →  SiteSelectResponse
  入参: mode('archive'|'forecast'，一期只认 archive) / date / start_time / speed
        corridor: {start, end, waypoints[]}  或 region: bbox
        radius_km(默认 15) / max_results(默认 3) / kind('base'|'relay')
  出参: sites[]: { role, lat, lon, name(geo.describe_point), level,
                   metrics{fly_ratio, worst_tke, nan_ratio, reach_km},
                   reach_km_actual, route_km, description }
         scanned_cells / elapsed_s / reason  ← 透出扫描规模，沿用 search_effort 那套措辞纪律
```

`search_effort` 那四条入口共用的措辞（归档 B1 追加之二）在这里必须延续：**没扫就是没扫**，
超时给部分结果要标"预算用尽前扫了 N 格"，不许给空数组装作"没有合适点"。

## 5. 性能预算（本方案的生死线）

现状对照，全部来自归档 B1 追加之五的同一次实测（2400 km 顶格用例，`assess_feasibility` 分段计时）：

| 阶段 | 调用次数 | 合计 |
| --- | --- | --- |
| `plan_path_segment`（含替代点扫描） | 28 | 33.0 s / 53.7 s |
| └ 其中 `_suggest_alt_bases` | 26 | **19~45 s** |
| `get_meteorology_grid` 取数 | 27 | 9.5~12.1 s |

新方案的开销模型：

| 项 | 次数 | 单价 | 合计 |
| --- | --- | --- | --- |
| 读场 | **1** | 0.35~0.45 s | ≤0.5 s |
| Pass 1 邻域统计 | 1 次向量化 | — | <0.1 s（303×543 盘统计） |
| Pass 2 A\* | **M=8** | 短程实测 0.4~0.5 s（三档同规模 0.42/0.44/0.52 s） | ≈3~4 s |
| 合计 | — | — | **<6 s** |

关键：**Pass 2 的 8 次规划共用一份注入场**，不会再出现"27 次读盘把 LRU 打穿"
（`_slab_cache` 12 条 / 384 MB，`_grid_cache` 4 条，每个不同 bbox 都 miss）。
所以选址比现有的替代点扫描**便宜一个数量级**，落在 `ASTAR_REQUEST_TIME_LIMIT_S=30` 内，
且不需要新加墙钟。

**但有一条必须设的闸**：整站有意不做鉴权、`/api/route/plan` 单 worker 串行吃本机 CPU、
公网出口约 2.5 Mbps（B8 与 `docs/公网访问部署.md`）。一个能指定任意 bbox 的扫描端点
= 给公网开了一个把本机堵死的口子。所以一期硬编码三件事：
① `SITE_MAX_SCAN_CELLS`（扫描格数上限，超了就要求缩小范围并明确报错）；
② 走廊模式只接受现有起终点，不接受自由 bbox 的全图扫描；
③ 沿用请求级墙钟，余额从入口往下传。**region 自由框选这个形态，我倾向一期不给。**

## 9. 风险与对策

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| 500 hPa 高空场被当成"地面适合起飞" | 答辩一问就崩（地面风与 5.6 km 高空风不是一回事） | 措辞纪律：一律说"高空气象口径下的候选站点"；`description` 里带"500 hPa"；**不承诺地面适飞结论** |
