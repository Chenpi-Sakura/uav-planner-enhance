## 0. 本方案新增的两项前置结论

M0 的核对项与性能假设已用真实数据验证，结论直接影响实现方式：

### 0.1 【已锁定】数据时间基准为 UTC（对应 §11 决策点 5）

**结论：NetCDF 时间标签为 UTC，北京时间 = UTC + 8。**

核对依据（`data/tibet_2022_upper_tc.nc`，2022 年逐小时，8760 帧）：

| 判据 | 方法 | 实测 | 理论值 | 结论 |
| --- | --- | --- | --- | --- |
| 时间轴是否为「固定偏移的钟表时」 | 温度日变化峰值时刻对经度回归 | 550hPa：**−0.0663 h/度**（n=240，经度 72°–102°） | UTC 与任何固定时区均为 **−1/15 = −0.0667 h/度** | 是固定时区，排除「地方太阳时」 |
| 偏移量是多少 | 峰值截距 + 近地层相位 | 600hPa 全域平均峰值标签 **8.4h**（经度均值约 88°E） | 按 UTC 解 → 当地 14.3h；按北京时解 → 当地 6.3h | 只有 UTC 解释物理成立 |
| 单点复核 | 拉萨 (29.65N, 91.13E) 600hPa | 峰值标签 **10h**，振幅 9.95K | 按 UTC 解 → 当地 16.1h；按北京时解 → 当地 8.1h | 近地日最高气温应出现在当地下午，UTC 解释成立 |

补充说明：`time` 变量 `units = "hours since 2022-1-1 00:00:00"`，无 `timezone` 属性，`standard_name=time` / `calendar=standard`，即数据本身不声明时区，只能靠物理判据反推。上表中「斜率」一项只能证明「时间轴是固定偏移的钟表时」（UTC 与北京时斜率相同），**定偏移量的是截距项**，故两条证据合起来才能定论。

**由此暴露一个既有口径问题**：功能一 `_batch_turbulence` / `_check_endpoints` / `planner._is_safe_at` 都是把用户输入的 `date` + `start_time` **直接当作数据标签**去查表，没有做时区换算。若用户输入的是北京时间，实际取到的是「北京时间 − 8 小时」的气象，窗口与曲线会整体偏移 8 小时——正是 §12 列的头号风险。

**处理建议（需用户确认，见 §8）**：在 `config.py` 增加单一常量组，默认按「输入 = 北京时间、数据 = UTC」换算，UI 标注数据口径。本次 M2 先落地常量与换算函数，并**只作用于 M2 新增链路**，不改动功能一既有行为（避免回归），功能一的统一留到 M5。

### 0.2 【已实测】性能瓶颈只在 NetCDF I/O，不在计算

实测环境：6 个变量各约 110GB，`data/` 位于 G 盘；bbox 取「拉萨→林芝」外围（28.7–30.7N / 89–96E）。

| 操作 | 耗时 |
| --- | --- |
| 3 变量（u/v/w）× 8 天 slab 读取（暖缓存） | **0.2 – 0.6 s** |
| 3 变量 × 8 天 slab 读取（首次冷读，与后端预加载竞争） | 约 6 s（个别情况达 112 s，见 §7 风险 R1） |
| 8 天 × 24 槽位 × 120 采样点向量化扫描（纯计算） | **0.06 s** |
| 全图 bbox（302×541）× 8 天 × 单变量 | 3.3 s |

结论：**必须按「最少文件读取 + 结果缓存」设计，计算量可忽略**。据此确定三条实现要点：

1. 扫描阶段只读 `u/v/w` 三个文件（TKE/EDR 由风速合成），**不读** `tc/rh/qvapor`；
2. 温湿度预警只在**推荐窗口确定后**读一次 `tc/rh`（仅该窗口所需时段），避免 5 文件全扫；
3. 按天 slab 结果做 LRU 缓存，键为 `(date, 变量, bbox 量化哈希)`，供曲线与多请求复用。

### 0.3 【已实测】EDR 硬约束在本数据集内实际不触发

| 时段 | TKE max | TKE p99 | TKE>1.0 占比 | EDR max |
| --- | --- | --- | --- | --- |
| 2022 年 7 月 | 2.67 | 1.09 | 1.48% | **0.022** |
| 2022 年 1 月 | 3.47 | 1.55 | — | — |

EDR 硬阈值为 0.3，实测最大值仅 0.022，**相差一个数量级**。即：功能二的「全程安全」判定实际由 TKE 单维主导，EDR 维度不构成约束。这不是缺陷（阈值口径与规划器一致，属数据本身的代理估算特性），但需在方案与 UI 中如实说明，避免答辩时被质疑「曲线里的 EDR 为什么永远很低」。

> 注：§5.4 响应样例中的 `max_edr` 字段保留，用于口径一致性与未来更换数据源。

def read_slab(self, var: str, times, bbox) -> SlabResult:

    """

def check_coverage(self, lat: float, lon: float) -> bool:
    """起降点是否落在气象数据经纬度范围内（带 0.25° 容差）。"""

### 2.4 算法流程（对应主计划 §5.2）

```
输入：start / end / date / speed / forecast_days / scan_step_hours / 可选阈值

1. 覆盖检查：起降点任一超出数据范围 → 直接返回 reason = data_coverage_insufficient

2. 几何基线（只算一次）
   a. 调 planner.plan_path_ex()，用期望日起飞时刻做一次 4D 规划
   b. found=True  → 用该路径作为几何基线，并沿用 planner 输出的 times/tkes/edrs
   c. found=False → 退回「直线路径离散化」，并标记 geometry_fallback=True
      （此时仍继续扫描：直线本身在某个时段可能是安全的）

3. 沿路径等距采样
   - 按 TW_SAMPLE_STEP_DEG 重采样，得到采样点列 P_i 与累计距离 s_i
   - 总时长 T = s_last / speed；各点到达时刻 t_i = t0 + (s_i / s_last) · T

4. 逐起飞时刻扫描（几何不变，只推进时间 + 查表）
   for t0 in 期望日 每个扫描步长：
       - 向量化查表：对每个采样点取 (t_i) 时刻的 TKE / EDR
       - 全程安全 = 全部采样点 TKE < tke_th 且 EDR < edr_th 且无 NaN
         （NaN 视为不安全，与 planner 一致）
       - 记录该槽位的 max_tke / max_edr / safe

5. 窗口聚合与推荐
   - 相邻的安全槽位合并为连续窗口
   - 推荐窗口 = 「窗口内路径最大 TKE 最低」者（平局取较早）
   - 推荐起飞时刻 = 该窗口内风险最低的槽位（平局取较早）
   - 备用时段 = 其余安全窗口，最多 TW_MAX_BACKUP_WINDOWS 个

6. 湍流曲线（仅推荐窗口存在时计算）
   - 评估域 = [推荐起飞 − TW_CURVE_PAD_HOURS, 预计降落 + TW_CURVE_PAD_HOURS]
   - 按 TW_CURVE_STEP_MINUTES 取时刻，对每个时刻算路径全体的 max TKE / max EDR / mean TKE

7. 温湿度与风速预警（仅推荐窗口存在时，且只读一次 tc/rh）
   - 对推荐窗口起降时刻附近，沿路径取 u/v（合成风速）、rh、tc
   - rh > WARN_RH_RAIN → 可能降水；rh > WARN_RH_ICE → 结冰/云中飞行
   - tc < WARN_TEMP_LOW → 低温提示；风速 > WARN_WIND_HIGH → 高空风提示

8. 当日无安全窗口时（不可飞分支）
   a. slot_analysis：当日每个扫描槽位一行（时刻 / max_tke / max_edr / 等级 / 是否安全）
   b. 逐日推演 date+1 … date+forecast_days，复用第 4–5 步（几何不变，仅换 slab）
   c. 最佳备选日期 = 推演期内首个存在安全窗口的日期；全无 → 输出逐日风险趋势 + 「建议推迟任务并等待气象更新」
   d. reason 三分类：全天无安全时段 / 航路本身永久阻塞（地形与 NaN 区）/ 数据覆盖不足
```

### 2.5 关键实现约束

1. **几何只算一次**：绝不在 24 × 7 的循环里重复调用 A*。这是性能达标的根本前提（§0.2 已证计算量可忽略，但不能重复跑 A*）。
2. **文件读取最少化**：扫描只用 `u/v/w`；`tc/rh` 只在推荐窗口后补读一次。
3. **向量化查表**：用「索引矩阵 + 花式索引」一次性取出 (n 采样点 × m 时次) 的 TKE/EDR，禁止 Python 双层循环逐点查表。
4. **NaN 语义与规划器一致**：NaN 视为不可飞行（对应地形/数据缺失），不静默按 0 处理。
5. **时区换算只在一个函数里**：`_to_data_time(user_datetime)`，全链路只此一处做偏移，便于一次性修正。

### 2.6 API 契约（`POST /api/assess/time-window`）

请求：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `start` / `end` | Point | 必填 | 起降点经纬度 |
| `date` | str | `2022-07-01` | 期望日期 |
| `speed` | float | 60.0 | 航速 km/h |
| `forecast_days` | int | 7 | 向前推演天数 |
| `scan_step_hours` | int | 1 | 扫描步长（默认走 config，传值可临时覆盖） |
| `tke_threshold` / `edr_threshold` | float? | None | 阈值覆盖，None 走 config |

响应（在主计划 §5.4 基础上补齐实际字段）：

```json
{
  "date": "2022-07-01",
  "has_window": true,
  "recommended": {
    "takeoff": "2022-07-01T07:00", "window": ["07:00", "11:00"],
    "landing": "2022-07-01T12:40", "level": "低风险",
    "max_tke": 0.42, "max_edr": 0.011
  },
  "curve": { "times": ["06:00", "..."], "max_tke": [], "max_edr": [], "mean_tke": [] },
  "backup_windows": [{ "start": "18:00", "end": "20:00", "level": "中风险", "max_tke": 0.55 }],
  "warnings": [{ "type": "humidity", "level": "info", "text": "14 时后相对湿度超过 80%，可能出现降水" }],
  "slot_analysis": [{ "time": "08:00", "max_tke": 0.5, "max_edr": 0.012, "level": "中风险", "safe": true }],
  "forecast": { "enabled": true, "days": [{ "date": "2022-07-02", "has_window": true,
                "best_window": ["07:00", "10:00"], "level": "低风险", "max_tke": 0.38 }] },
  "reason": null,
  "meta": { "geometry_fallback": false, "route_km": 311.6, "flight_time_h": 5.19,
            "n_samples": 120, "scan_step_hours": 1, "data_label_is_utc": true, "tz_offset_hours": 8 }
}
```

`reason` 取值：`null` / `no_safe_slot`（全天无安全时段）/ `route_permanently_blocked`（地形或 NaN 区封死）/ `data_coverage_insufficient` / `od_too_close`（起终点离散不出两点）。

起终点直线距离不足 `MIN_OD_KM`（5 km ≈ 一个气象格）时在 HTTP 入口直接 400，不进扫描——
否则它会以一条 0 km 的"可飞航线"通过全链路（实测重合坐标：`/api/route/plan` 返回
`total_distance: 0, reason: null`）。`od_too_close` 只在规划器失败、退回直线离散化仍塌成一点时才给。

| --- | --- | --- | --- |
| R1 | 冷读 + 与后端其它请求并发时 I/O 争用（实测出现过单次 112 s，背景是启动预加载在读 660GB） | 接口超时 | ① 只读必要变量与 bbox；② LRU 缓存；③ 接口层加超时保护与友好降级；④ 避免与首次预加载同时压测 |
| R2 | 时区口径若判断有误 | 窗口与曲线整体偏移 8 小时 | 已用两条独立物理判据锁定 UTC（§0.1）；常量集中、可一键关闭换算；UI 明示口径 |
| R3 | 直线兜底几何下的扫描结论被误读 | 用户以为「规划出了安全航线」 | 响应中输出 `geometry_fallback` 标记，前端在兜底时明确提示「未找到安全航线，以下按时段分析结果仅供参考」 |
| R4 | 扫描步长与数据粒度不一致（1h vs 会议口径 3h） | 与需求描述不符 | 步长配置化。**2026-09-24 定案取 1h**（见 `docs/backlog.md` B2b）：核对文件证实数据本就是逐小时，会上的"3 小时"是展示口径不是分辨率；对外要 3 小时一档就在展示层归并 |
| R5 | 7 天推演期间跨月/跨年 | 索引越界或取到空 slab | 以数据集时间轴为准做边界检查，超出范围的天直接标记「无数据」而非报错 |
